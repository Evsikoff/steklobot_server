# Стекольщик — сервер бота с панелью оператора

Замена n8n-процесса `auto-glass-bot` на самостоятельный сервер: Telegram-бот, оркестратор
запросов к LLM, хранение в Supabase и веб-панель для менеджеров.

Что делает сервер:

- принимает сообщения клиентов из Telegram, ведёт по каждому клиенту диалог и зеркалит его
  в форум-топик чата менеджеров (как в n8n-версии);
- **понимает голосовые и фото**: голосовое расшифровывает Gemini 3.5 Transcribe,
  автомобиль на фото распознаёт Gemini (`GEMINI_MODEL`), и дальше запрос идёт обычным
  путём — отвечает бот всегда текстом;
- **оркеструет запросы к LLM**: сообщения клиента копятся в буфере, а если клиент пишет снова
  до ответа модели — текущий прогон вытесняется и новый уходит в LLM сразу со **всеми N**
  накопленными сообщениями;
- **проверяет валидность JSON** от модели и, если он невалиден, просит переделать
  (до `LLM_MAX_JSON_RETRIES` раз), передавая модели причину отказа;
- цены берёт **только** из прайса — LLM возвращает id строк, текст с ценами собирает сервер;
- эскалирует диалог менеджеру и показывает такие запросы отдельной вкладкой;
- пишет **каждое** внешнее взаимодействие (Telegram, LLM, прайс, Supabase) в журнал с кодом
  ответа, длительностью и текстом ошибки.

## 1. Панель оператора

| Вкладка | Что показывает |
| --- | --- |
| **Чаты** | Список диалогов, режим каждого (AI / Ручной) с переключателем, лента сообщений, ответ клиенту от имени менеджера. Значок «LLM думает» — идёт прогон. |
| **Менеджеру** | Дубль всех запросов к менеджеру: причина, суть, что писал клиент, что ответил бот. Статусы «новый → в работе → закрыт». |
| **Оркестрация** | Живое состояние буферов по каждому чату и лента прогонов: сколько сообщений склеено, таймлайн этапов с длительностями, переспросы невалидного JSON, цепочки вытеснения. |
| **Интеграции** | Переключатель провайдера LLM, состояние Supabase / Telegram / прайса / LLM и журнал внешних вызовов с фильтром «только ошибки». |

Вход по паролю `ADMIN_PASSWORD`, живое обновление по WebSocket.

## 2. Как работает оркестрация

```
сообщение клиента
   ↓
буфер чата  ──── пришло ещё одно? ──→ активный прогон отменяется (статус superseded)
   ↓                                   и буфер растёт
окно склейки ORCHESTRATOR_DEBOUNCE_MS
   ↓
прогон: контекст (история + прайс) → LLM → проверка JSON ─невалиден→ просим переделать
   ↓                                              ↑____________________|
сборка ответа из строк прайса → отправка клиенту → зеркало в топик → эскалация (если нужна)
```

Важные детали:

- прогон, начавший **отправку** ответа, уже не отменяется — клиент не получит два ответа
  и не останется без ответа;
- если менеджер перевёл диалог в ручной режим во время прогона, автоответ не уходит;
- если LLM так и не вернула валидный JSON, клиент получает вежливый ответ, диалог переводится
  в ручной режим и создаётся запрос менеджеру с причиной `ai_unavailable`;
- если прайс недоступен, бот не выдумывает цены — эскалация `price_source_unavailable`;
- если клиент спросил про несколько стёкол сразу («лобовое и заднее»), ответ разбивается
  на блоки по типу стекла — модель возвращает id по всем запрошенным типам;
- на запрос «самое дешёвое» модель возвращает все подходящие строки и `selection: "cheapest"`,
  а сервер сам считает суммы и показывает самый дешёвый вариант и самый дешёвый из наличия
  (арифметика и отбор — на сервере, не в тексте модели);
- голосовое и фото автомобиля бот распознаёт сам (см. раздел 3.1) и ведёт по ним обычный
  подбор; оригинал всё равно копируется в топик через `copyMessage`, чтобы менеджер мог
  перепроверить расшифровку на слух, а машину — глазами. Если распознавание уложилось в
  `RECOGNITION_QUICK_REPLY_MS`, клиент сразу получает расшифровку или распознанную машину,
  не дожидаясь основного LLM-прогона;
- остальные вложения (файл, видео, кружок, геопозиция) — и те голосовые с фото, которые
  распознать не удалось, — бот прочитать не может: копия уходит в топик менеджера,
  факт пишется в историю диалога, тред переводится в ручной режим с эскалацией
  `attachment_received`, а клиент получает предупреждение, что ответит менеджер.
  Стикеры и GIF только зеркалятся в топик. Альбом копируется целиком, но эскалация
  и ответ клиенту — один раз;
- вопрос про уже показанные варианты («в чём разница?») — не повод присылать тот же список:
  модель получает id из прошлого ответа и объясняет отличия текстом (`not_requested`), а если
  она всё же вернула те же строки, сервер сам отвечает, чем варианты отличаются (бренд и опции),
  без повтора цен. Если тот же вопрос приходит снова — эскалация `repeat_question` и менеджер.

## 3. Провайдеры LLM

Поддерживаются два, переключаются на вкладке «Интеграции» без перезапуска:

| Провайдер | Что использует |
| --- | --- |
| **Gemini** | `GEMINI_API_KEY`, `GEMINI_MODEL` — Google Generative Language API |
| **API Bazaar** | `API_BAZAAR_URL`, `API_BAZAAR_KEY`, `API_BAZAAR_MODEL` — OpenAI-совместимый `/chat/completions` |

Как это устроено:

- выбор хранится в `app_settings.llm_provider` и переживает перезапуск;
- переключиться на провайдера без заполненных секретов нельзя — панель покажет,
  каких переменных не хватает;
- если сохранённый провайдер перестал быть настроенным (секреты убрали), при старте
  происходит откат на рабочий, с ошибкой в логе — бот продолжает отвечать;
- провайдер фиксируется на весь прогон: переключение во время работы не меняет модель
  на середине цепочки переспросов JSON;
- в `runs.llm_model` пишется `провайдер:модель`, например `apibazaar:gpt-5.6-luna`,
  поэтому по журналу прогонов видно, чем именно отвечали;
- вызовы обоих провайдеров попадают в журнал внешних взаимодействий под своими
  именами (`gemini`, `apibazaar`), фильтр «LLM» на вкладке «Интеграции» показывает оба.

## 3.1. Голосовые и фото

Оба распознавания идут через Gemini и используют **тот же** `GEMINI_API_KEY`. Они не
зависят от переключателя провайдера: даже когда ответы генерит API Bazaar, голос и фото
разбирает Gemini. Состояние обоих видно на вкладке «Интеграции».

**Голосовые — `gemini-3.5-transcribe`.** Telegram отдаёт голосовое в поддерживаемом Gemini
формате Ogg/Opus. Сервер загружает исходный файл в Gemini Files API и передаёт его целиком
файловой модели транскрипции в режиме Smart. Перекодирование в PCM и Live WebSocket больше
не используются: для уже записанного Telegram-сообщения они только добавляли точки отказа.
После ответа временный файл удаляется из Files API. Расшифровка сохраняется как обычное
сообщение клиента (`meta.source = "voice"`), дублируется в топик с пометкой 🎤 и попадает
в тот же оркестратор — со склейкой, вытеснением и подбором по прайсу.

**Фото — обычная мультимодальная Gemini (`VISION_MODEL`, по умолчанию `GEMINI_MODEL`).**
Отдельный вызов с картинкой возвращает JSON с маркой, моделью, поколением, диапазоном лет,
типом кузова и видимым повреждением. Из него собирается блок `[Фото: ...]`, который
подмешивается к подписи клиента — дальше подбор стекла идёт ровно так же, как для текста.
Промпт отдельно оговаривает, что это распознавание, а не слова клиента, и что **год по фото
не определяется**: если клиент не назвал год текстом, бот его переспросит. Берётся самый
крупный вариант фото; изображение, присланное файлом «без сжатия» (jpeg/png/webp/heic),
тоже распознаётся.

Быстрое распознавание фото или голоса отдельно подтверждается клиенту. Окно задаётся
`RECOGNITION_QUICK_REPLY_MS` (по умолчанию 10 секунд): успевший результат приходит сразу,
а основной ответ с вопросами и вариантами стекла формируется обычным LLM-прогоном. Это
техническое подтверждение не подмешивается в историю LLM и не заменяет последний прайс.

Если распознать не удалось, причина уходит и в топик менеджеров (прямо в строке «Клиент прислал
фото…»), и в журнал внешних вызовов. В журнал пишется не только отказ HTTP: разбор ответа —
отдельное событие `vision:<модель>:parse`, иначе пустой ответ модели или неразобранный JSON
нигде бы не отражались и отказ выглядел бы как «вызовов с ошибкой нет».
Клиенту бот отвечает просьбой написать текстом — но если у фото была подпись, диалог
продолжается по ней, без остановки.

## 4. Supabase

Выполните `sql/001_init.sql` в **Supabase → SQL Editor → New query → Run**. Скрипт
идемпотентный, повторный запуск безопасен.

Создаются таблицы:

| Таблица | Назначение |
| --- | --- |
| `threads` | диалоги (замена n8n-таблицы `auto_glass_threads`) |
| `messages` | история переписки (замена JSON-колонки `history`) |
| `runs` | прогоны оркестратора |
| `run_events` | этапы прогонов — из них рисуется вкладка «Оркестрация» |
| `escalations` | запросы к менеджеру |
| `external_events` | журнал внешних вызовов и ошибок |
| `app_settings` | глобальные настройки |

RLS включён, публичных политик нет: сервер ходит с service-role ключом, анонимный ключ
не даёт доступа ни к чему.

## 5. Секреты для Northflank

Создайте **Secret group** и привяжите её к сервису. Обязательные (без них сервер не стартует
и напишет в лог, каких именно не хватает):

| Переменная | Что это и где взять |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather, вида `8912500576:AAEm...`. В n8n-версии он был вшит в URL ноды `Create Forum Topic` — возьмите оттуда или перевыпустите. |
| `TELEGRAM_MANAGER_CHAT_ID` | ID супергруппы менеджеров с включёнными темами (Topics), вида `-1001234567890`. Бот должен быть в ней админом с правом «Управление темами». |
| `TELEGRAM_WEBHOOK_SECRET` | Придумайте случайную строку (32+ символа). Сервер сверяет её с заголовком `x-telegram-bot-api-secret-token` и отбрасывает чужие запросы. |
| `SUPABASE_URL` | Supabase → Project Settings → Data API → Project URL. |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API keys → `service_role`. **Секретный ключ**, только для сервера. |
| `GEMINI_API_KEY` | Google AI Studio → Get API key. Тем же ключом работают распознавание голосовых и фото. |
| `API_BAZAAR_URL` | Только если используете второго провайдера: base URL, например `https://api.apibazaar.shop/v1`. Принимается и полный путь до `/chat/completions`. |
| `API_BAZAAR_KEY` | Ключ API Bazaar. |
| `API_BAZAAR_MODEL` | Имя модели, например `gpt-5.6-luna`. |
| `PRICE_LIST_CSV_URL` | Ссылка на прайс в формате CSV: `https://docs.google.com/spreadsheets/d/<ID>/export?format=csv&gid=0`. Таблица должна быть доступна по ссылке. Колонки: `id, make, model, year_from, year_to, glass_type, features, brand, price_glass, price_work, in_stock`. |
| `ADMIN_PASSWORD` | Пароль для входа в панель. |
| `SESSION_SECRET` | Случайная строка (32+ символа) для подписи cookie сессии. |

Необязательные (есть значения по умолчанию):

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `PUBLIC_BASE_URL` | — | Публичный адрес сервиса. По нему сервер сам регистрирует webhook при старте. Заполняется **после первого деплоя** — Northflank выдаёт домен вида `p01--steklobot--xxxxxxxx.code.run` со случайной частью, узнать его заранее нельзя. Без него сервер работает, но webhook нужно выставить вручную. |
| `TELEGRAM_IGNORED_TOPIC_IDS` | `1,2` | Топики чата менеджеров, которые бот не обрабатывает (через запятую). Топик `1` — служебный General супергруппы. Сообщения в этих топиках полностью игнорируются: режим диалога не меняется, клиенту ничего не пересылается, предупреждений в чат бот не пишет. Пустое значение отключает фильтр. |
| `PORT` | `8080` | порт сервиса |
| `GEMINI_MODEL` | `gemini-3.7-flash` | модель Gemini; в n8n была `models/gemini-3.7-flash` |
| `LLM_PROVIDER` | `gemini` | провайдер при самом первом старте. Дальше значение берётся из таблицы `app_settings` и меняется переключателем в панели. |
| `API_BAZAAR_JSON_MODE` | выкл. | `1` — слать `response_format: json_object`. Не все модели за прокси это поддерживают, поэтому по умолчанию выключено: корректность JSON и так обеспечивают валидатор и переспрос. |
| `LLM_TEMPERATURE` | `0.1` | |
| `LLM_MAX_OUTPUT_TOKENS` | `1024` | |
| `LLM_TIMEOUT_MS` | `45000` | таймаут одного вызова модели |
| `LLM_MAX_JSON_RETRIES` | `2` | сколько раз просим переделать невалидный JSON |
| `TRANSCRIBE_ENABLED` | вкл. | `0` — не распознавать голосовые, отвечать «понимаю только текст» |
| `TRANSCRIBE_MODEL` | `gemini-3.5-transcribe` | файловая модель распознавания речи. Старое значение `gemini-3.5-transcribe-live` автоматически переводится на неё для совместимости с уже созданными Secret groups |
| `TRANSCRIBE_LANGUAGE_CODES` | `ru-RU` | подсказка по языку, BCP-47 через запятую. Пусто — автоопределение |
| `TRANSCRIBE_MAX_DURATION_SEC` | `600` | голосовые длиннее не отправляем |
| `TRANSCRIBE_TIMEOUT_MS` | `60000` | общий бюджет на одно распознавание |
| `VISION_ENABLED` | вкл. | `0` — не распознавать фото |
| `VISION_MODEL` | значение `GEMINI_MODEL` | модель для фото; должна быть мультимодальной |
| `VISION_TIMEOUT_MS` | `45000` | таймаут распознавания фото |
| `VISION_MAX_OUTPUT_TOKENS` | `2048` | лимит ответа модели на фото. У думающих моделей рассуждение тратится из этого же бюджета: на тесном лимите ответ приходит пустым с `finishReason=MAX_TOKENS` |
| `RECOGNITION_QUICK_REPLY_MS` | `10000` | если распознавание фото или голоса уложилось в это окно, сразу отправить его результат клиенту. `0` отключает отдельное подтверждение |
| `ORCHESTRATOR_DEBOUNCE_MS` | `1200` | окно склейки сообщений клиента |
| `ORCHESTRATOR_MAX_BATCH` | `10` | максимум сообщений в одном прогоне |
| `HISTORY_LIMIT` | `20` | сколько последних сообщений уходит в промпт |
| `PRICE_LIST_CACHE_TTL_MS` | `120000` | кэш прайса |
| `SUPABASE_TIMEOUT_MS` | `15000` | таймаут запроса к Supabase |
| `SESSION_TTL_MS` | `604800000` | срок жизни сессии панели (7 дней) |

### Порядок первого деплоя

1. Создайте сервис из этого репозитория, порт `8080` пометьте **Public** — без публичного
   порта Northflank не выдаст домен.
2. Задайте все обязательные секреты, кроме `PUBLIC_BASE_URL`. Сервис запустится и напишет
   в лог `PUBLIC_BASE_URL не задан`; панель уже доступна, вкладка «Интеграции» покажет
   состояние Supabase, Telegram и прайса.
3. Скопируйте домен: сервис → **Ports & DNS** → строка порта `8080`.
4. Добавьте секрет `PUBLIC_BASE_URL=https://<домен>` — со схемой, без слэша на конце
   и без пути `/telegram/webhook`.
5. Перезапустите сервис. В логе появится `webhook Telegram установлен: ...`.

Проверить webhook: `curl "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"` — поле `url`
должно совпадать с вашим адресом, а `last_error_message` отсутствовать.

Если есть свой домен, привяжите его к порту заранее (Ports & DNS → Custom domains) и
пропишите `PUBLIC_BASE_URL` сразу — тогда второй перезапуск не нужен.

### Настройки сервиса Northflank

- **Build**: Dockerfile в корне репозитория.
- **Port**: `8080`, HTTP, публичный.
- **Health check**: `GET /healthz` (уже прописан и в Dockerfile).
- **Instances**: **1**. Оркестратор держит буферы сообщений в памяти процесса; на нескольких
  репликах один клиент может попасть в разные инстансы, и склейка сломается. Для нескольких
  реплик понадобится общая очередь (Redis) — сейчас не реализовано.

## 6. Запуск

Локально:

```bash
npm install
cp .env.example .env   # заполнить значения
npm run build
npm start
```

Панель — на `http://localhost:8080`, вход по `ADMIN_PASSWORD`.

Локально `PUBLIC_BASE_URL` обычно недоступен Telegram — используйте туннель (ngrok/cloudflared)
и укажите его адрес, либо выставьте webhook вручную:

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=<PUBLIC_URL>/telegram/webhook&secret_token=<TELEGRAM_WEBHOOK_SECRET>"
```

## 7. Команды в топике менеджеров

| Команда | Действие |
| --- | --- |
| `/ai` | вернуть автоответы |
| `/human` или `/stop` | выключить автоответы |
| любое другое сообщение | уходит клиенту, диалог переводится в ручной режим |

Топики из `TELEGRAM_IGNORED_TOPIC_IDS` (по умолчанию `1` и `2`) бот не обрабатывает вовсе —
в них можно свободно переписываться, команды там не действуют.

То же самое доступно из панели: переключатель режима и поле ответа во вкладке «Чаты».

## 9. Чего сознательно нет

- **Горизонтального масштабирования.** Состояние оркестратора — в памяти процесса
  (см. раздел про Instances).
- **Остальных медиа.** Распознаются голосовые и фото; видео, кружки, документы, стикеры
  и геопозиция уходят менеджеру целиком с эскалацией `attachment_received`.
  Голосовые от менеджера в топике тоже не расшифровываются.
- **Ответа голосом.** На голосовое бот отвечает текстом.
- **Прайса в Supabase.** Источник цен остался Google Sheets CSV, как в n8n-версии.
